\subsection{Definisi dan Karakteristik Fungsi Hash}

\crypt{Fungsi Hash} kriptografis adalah algoritma matematika yang memetakan data dengan ukuran arbitrer (input/pesan $M$) menjadi string karakter dengan panjang tetap (output), yang dikenal sebagai \crypt{hash value}, \crypt{message digest}, atau \crypt{fingerprint}. Secara matematis, fungsi hash $H$ dapat dinyatakan sebagai:
\begin{equation}
  h = H(M)
\end{equation}
di mana $M \in \{0, 1\}^*$ dan $h \in \{0, 1\}^n$ ($n$ adalah panjang tetap digest).

Berbeda dengan fungsi hash dalam struktur data (seperti \textit{hash map}), fungsi hash \textbf{kriptografis} harus memenuhi persyaratan keamanan yang sangat ketat agar tidak dapat dimanipulasi oleh penyerang.

\subsection{Properti Keamanan Fungsi Hash}

Sebuah fungsi hash dikatakan aman secara kriptografis jika memenuhi tiga properti fundamental berikut:

\begin{enumerate}
    \item \textbf{Pre-image Resistance (One-Wayness)}:
    Diberikan sebuah nilai hash $h$, secara komputasi tidak mungkin untuk menemukan pesan $M$ sedemikian sehingga $H(M) = h$. Dengan kata lain, fungsi hash harus bersifat satu arah; informasi asli tidak dapat dipulihkan dari digest-nya.

    \item \textbf{Second Pre-image Resistance (Weak Collision Resistance)}:
    Diberikan sebuah pesan $M_1$, secara komputasi tidak mungkin untuk menemukan pesan berbeda $M_2 \neq M_1$ sedemikian sehingga $H(M_1) = H(M_2)$. Ini menjamin bahwa penyerang tidak dapat memalsukan dokumen yang memiliki hash yang sama dengan dokumen asli.

    \item \textbf{Collision Resistance (Strong Collision Resistance)}:
    Secara komputasi tidak mungkin untuk menemukan \textit{dua pesan apa pun} $M_1$ dan $M_2$ (di mana $M_1 \neq M_2$) sedemikian sehingga $H(M_1) = H(M_2)$. Properti ini lebih kuat daripada \textit{second pre-image resistance}.
\end{enumerate}

\subsection{Analisis Efek Longsoran (\textit{Avalanche Effect})}

Salah satu indikator kualitas fungsi hash adalah \textbf{Avalanche Effect}. Sifat ini mensyaratkan bahwa perubahan sekecil apa pun pada input (misal: mengubah satu bit saja) harus menghasilkan perubahan yang drastis dan tidak terprediksi pada output. Secara statistik, rata-rata 50\% dari bit-bit pada output harus berubah.

Jika sebuah fungsi hash tidak memiliki efek longsoran, penyerang dapat menggunakan teknik analisis diferensial untuk menebak struktur input berdasarkan perubahan kecil pada output.

\subsection{Implementasi dan Kegunaan dalam Keamanan Informasi}

Fungsi hash tidak digunakan untuk menyembunyikan data (karena bukan enkripsi), melainkan untuk menjamin \textbf{integritas} dan \textbf{autentikasi}:

\begin{itemize}
    \item \textbf{Verifikasi Integritas Berkas}: Distribusi perangkat lunak sering menyertakan nilai hash (misal: SHA-256) di samping file unduhan. Pengguna dapat menghitung hash file yang diterima; jika hasilnya berbeda satu bit saja, maka file tersebut telah rusak atau dimodifikasi oleh pihak ketiga.
    \item \textbf{Penyimpanan Kata Sandi Aman}: Sistem modern tidak menyimpan password dalam teks polos. Password di-hash (dan biasanya ditambah \textit{salt}) sebelum disimpan. Saat login, sistem menghitung hash dari password yang dimasukkan pengguna dan membandingkannya dengan hash yang tersimpan.
    \item \textbf{Komponen Tanda Tangan Digital}: Karena menandatangani pesan besar secara asimetris sangat lambat, yang ditandatangani adalah \textit{hash} dari pesan tersebut. Ini menjamin bahwa pesan belum berubah dan pengirimnya sah.
\end{itemize}

\begin{aktivitas}
  \item \textbf{Analisis Sensitivitas}: Gunakan alat penghitung hash SHA-256. Hitung hash untuk string \texttt{"Kriptografi\_ITB\_2026"} dan \texttt{"Kriptografi\_ITB\_2027"}. Amati betapa berbedanya kedua hasil tersebut meskipun hanya satu karakter yang berubah. Hitung berapa banyak karakter yang sama antara kedua output tersebut.
\end{aktivitas}

\begin{latihan}
  \item Jelaskan perbedaan antara \textit{Second Pre-image Resistance} dan \textit{Collision Resistance}! Mengapa properti kedua lebih sulit untuk dicapai daripada properti pertama?
  \item Mengapa penggunaan fungsi hash saja tidak cukup untuk mengamankan penyimpanan password terhadap serangan \textit{Rainbow Table}? Jelaskan peran \textit{salting} dalam mengatasi masalah ini!
  \item Misalkan sebuah fungsi hash memiliki output 16 bit. Berdasarkan \textit{Birthday Paradox}, berapa jumlah input yang harus dicoba oleh penyerang untuk menemukan kolisi dengan peluang 50\%?
  \item Jika sebuah fungsi hash memiliki \textit{pre-image resistance} yang kuat tetapi tidak memiliki \textit{collision resistance}, apakah fungsi tersebut masih bisa digunakan untuk menyimpan password? Berikan analisis Anda!
\end{latihan}
